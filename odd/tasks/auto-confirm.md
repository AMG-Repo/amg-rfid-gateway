# Automatic entry/exit confirmation (gateway)

Optional automatic mode in the local panel: a tag pass that ends (no reads for a while) is confirmed by the gateway itself through the normal confirm path. Finding G3 of the pilot review.
Branch: feat/auto-confirm (from origin/main c8178b5), worktree /home/jesus/Work/amg-rfid-gateway-worktrees/auto-confirm. Issue #150.

## Specs

- S1. User (2026-11-26): "podemos hacer que en la raspberry tengamos la opcion de que el envio de la confirmacin de ingreso y salida de las tags sea automatico o manuan, es decir actualmente para una confirma tenemos que presionar el boton de confirmar ese seria manual podmeo agregar un boton que active un hook que despues de cierto tiempo sin lectura por ejemplo 1 minuto automaticamente confirme y mande la entrada y salida al vps? o ya tenemos la funcionalidad?"
- S2. Direction, user choice "Por estado del tag (Recomendado)": "Si el gateway tiene el kanban en el almacén, es salida; si no, es entrada. Funciona con la antena única de hoy."
- S3. Trigger, user choice "1 min sin lecturas (Recomendado)": "Lo que propusiste: el tag deja de leerse durante 1 minuto y se confirma. El tiempo se podría ajustar desde la config."
- S4. Filter, user choice "Mínimo de lecturas (Recomendado)": "Solo se confirma si el tag se leyó varias veces en esa pasada (por ejemplo 3 o más). Si no, queda para confirmar a mano."
- S5. Switch, user choice "Botón en el panel (Recomendado)": "Un interruptor Manual / Automático en el panel local, con login de escritura. Se guarda en el gateway y sobrevive reinicios."
- S6. Agreed design (parent proposal, user "dale arranca"): manual mode behaves exactly as today; tags without a kanban are never auto-confirmed; auto confirms use the same path as manual ones (confirmation_id + occurred_at, queue, retries); the panel shows the active mode and marks automatic movements in today's history; idle time (1 min) and minimum reads (3) adjustable in the config.
