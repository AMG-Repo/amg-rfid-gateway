# Account-change proposal: reject-only local boundary

`proposeAccountChange` is a separate package-private, non-authorizing proposal. It does not call the existing mode-only planner or fixture transaction, and has no production apply or service caller. A valid sealed `content_equal` observation still receives `missing_whole_tree_inventory` and `missing_authenticated_target_identity`; invalid, altered or unsupported content observations receive `untrusted_content_observation`. Every result has zero transitions and `ApplyEligible=false`.

`ContentObservation` compares package bytes and observes selected package/config metadata. Its seal does not attest to a complete data tree, per-object group GIDs, target account provisioning, membership or current device state. The separate typed object shape holds a relative identity and explicit before/intended UID, GID and mode, but synthetic instances are not provenance; no production path accepts a caller-supplied inventory, target identity or verified flag as authority. Unsupported objects and incomplete, stale or ambiguous inventories cannot become a positive proposal through this boundary.

A future collector would need authenticated target numeric identity and a fresh, bounded complete per-object tree inventory, with the object, ancestry, alias, ACL, mount and writer controls in the [account access contract](homebrew-deployment-account-access.md). Separate durable recovery, service and device gates remain unresolved. This document supplies no migration, inverse, activation or privileged operation; DEVICE-GATE remains **NO-GO**.
